# 修正方案：内容列规则与页面紧凑度（2026-10-12）

## 用户反馈

> 正文部分为什么没有居中，而且中间区域周围有那么多空白，紧凑一点，现在显得很空旷

## 实测证据（150% DPI，窗口 1180x800 DIP）

| 元素 | 实测矩形（物理像素） | 说明 |
|---|---|---|
| 窗口 | x 228..1998（1770） | 1180 DIP 宽 |
| 内容区（导航栏之后） | x 528..1998（1470） | 中心 x = 1263 |
| 空态标题"把视频拖到这里" | x 1416..1631 | 中心 x = **1523** |
| 空态按钮 | x 1419..1627 | 中心 x = 1523 |

结论：空态块比内容区中心**偏右 260 物理像素（约 173 DIP）**，并且只占内容区
1470 像素中的 215 像素宽——视觉上就是"一个浮在右边的孤岛，四周全是留白"。

## 根因

`ConvertPage.xaml` 的滚动内容是一个 `StackPanel MaxWidth="720"`，空态又是它内部
一个 `HorizontalAlignment="Center"` + `Margin="0,80,0,0"` 的子 `StackPanel`。
窄列 + 顶部固定外边距的组合，让空态既没有利用横向空间，也没有垂直居中，
变成一个悬在右上方的孤岛。同类问题也存在于设置页（全宽卡片 + 窄列混用）。

## 目标布局

### 统一内容容器规则（三页一致）

```xml
<ScrollViewer Style="{StaticResource PageScrollViewerStyle}">
    <Grid Padding="24,20" MaxWidth="1280" HorizontalAlignment="Center">
        <!-- 页面内容 -->
    </Grid>
</ScrollViewer>
```

- 不再用 `MaxWidth=720` 的窄列；内容**填满**可用宽度（上限 1280 DIP，超宽屏才留边）
- 1180 DIP 窗口下内容区约 980 DIP < 1280，因此完全铺满，不再出现悬浮窄列
- 统一内边距 24/20，三页一致

### 转换页 · 空态：把留白变成拖放区

空态不再是一段居中的文字块，而是**撑满内容区的拖放面板**：

```
┌ content（铺满） ────────────────────────────────────────────┐
│ ┌ 拖放面板 Border（铺满，1px 细边框 + 卡片底色，圆角 8）──┐ │
│ │                    [大图标 56]                          │ │
│ │                把视频拖到这里                            │ │
│ │        支持 mp4 / mov / mkv / avi …（MaxWidth 420）      │ │
│ │                 [ 选择视频文件 ]                         │ │
│ └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- 面板 `HorizontalAlignment/VerticalAlignment = Stretch`，内层提示 `Center`
- 去掉 `Margin="0,80,0,0"` 这类固定外边距
- 拖放面板同时充当视觉拖放目标（拖拽高亮为后续 P1 项）

### 转换页 · 有文件态：两列填满宽度

```
┌ 文件卡（*） ─────────────────────┐ ┌ 参数卡（固定 400 DIP）──────┐
│ [缩略图 220x124] 文件名  [添加]   │ │ 容器格式   […..]            │
│   时长 · 分辨率 · 大小            │ │ 视频编码器 […..]            │
│   输出路径                        │ │ 质量  [====] 23             │
│   缩略图时间点 [4.32] [重新截取]  │ │ [高级选项 ▾]                │
│   [详细信息 ▾]（键值两列铺满）    │ │ 参数摘要                    │
└───────────────────────────────────┘ └─────────────────────────────┘
```

- 宽窗（≥1120 DIP）：`Grid` 两列，左 `*`、右 `Auto`（参数卡固定 400 DIP）
- 窄窗（<1120 DIP）：参数卡落到第二行（单列堆叠），用 `AdaptiveTrigger` 切换
- 「详细信息」的键值表改为**两列铺满**，不再挤在左侧

### 队列页 / 设置页

- 套用同一容器规则（内边距 24/20，上限 1280，居中）
- 设置页卡片内的"标签 + 控件"行不再让控件无限拉伸：控件给 `MaxWidth`（约 420），
  右侧留白由说明文字或空列吸收，避免出现超宽输入框

## 不做

- 不改 VM 契约、不动 Core、不新增功能
- 不做拖拽高亮、InfoBar、设计令牌、队列「更多」菜单（仍属 P1/P2）
- 不删除任何既有 AutomationId

## 验收

- [ ] 1180x800 DIP 下：空态拖放面板铺满内容区，四周无大面积留白
- [ ] 1180x800 DIP 下：有文件态两列并排，右侧无空列
- [ ] 800x600 DIP 下：参数卡堆叠到第二行，无横向裁切，"开始转换"仍可见
- [ ] 1600x1000 DIP 下：内容列以 1280 为上限居中，不出现超宽输入框
- [ ] 三页内边距一致；构建 0/0 + 142 测试通过

## 实施记录（2026-10-12）

### 第一轮：三页容器统一 + 空态重做 + 有文件态两列

- 空态改为铺满内容区的拖放面板（不再居中孤岛）
- 有文件态宽窗两列（文件卡 `*` / 参数卡 400 DIP），窄窗用 `AdaptiveTrigger` 堆叠
- 设置页改为 Windows 11 式行结构（标题+说明在左、控件右对齐）
- `详细信息` 键值表改为铺满卡片的多列布局

### 第二轮：修掉第一轮引入的溢出（实测发现）

把 `MaxWidth="1280" HorizontalAlignment="Stretch"` 直接加在**滚动内容根**上，
在 1600x1000 DIP 下导致内容右移并溢出：

| 元素 | 实测（物理像素，窗口 40..2440） |
|---|---|
| 设置行描述"硬件加速" | 971..2422（宽 1451 = 967 DIP） |
| 复选框"强制使用软件编码" | 矩形为 ∞（被推出窗口，点不到） |

修正：滚动内容根只保留 `Padding="24,20"`（宽度恒等于视口），
宽度限制一律下沉到控件层；同时给并排的两张卡片加 `VerticalAlignment="Top"`，
消除内容较少一侧被拉高留下的空段。同一缺陷也存在于底部操作条的内层 Grid，一并移除。

### 最终验收结果

- 1180x800 DIP：空态拖放面板铺满、提示居中（实测居中偏差 <6 DIP，修正前为 260 物理像素）
- 1180x800 DIP：有文件态两列并排，卡片各自贴合内容高度
- 800x600 DIP：参数卡正确堆叠到第二行，"开始转换"常驻可见
- 1600x1000 DIP：内容贴左铺满，复选框/浏览按钮矩形有限且在窗口内（可点击）
- 构建 0 警告 0 错误；142 测试全绿

# 修正方案：转换页 / 队列页职责划分（2026-10-12）

## 用户诊断（原话要点）

> 问题不在配色和圆角，而在信息架构——转换页和队列页的职责没分清，
> 导致两个页面互相打架。骨架（NavigationView + 三页）是对的，
> 把"添加到队列"和"开始转换"拆开，这两个页面就各司其职了。

## 采纳方案：A（转换页 = 单文件预览 + 参数，开始转换只在队列页）

理由：改动最小、职责最清晰；方案 B（合并成单页）在笔试时间窗内风险过高。

## 修复清单（按用户给定顺序）

### P0-1 转换页不再承担"开始转换"

- 转换页底部操作条去掉蓝色主按钮「开始转换」；开始转换只保留在队列页
- 转换页改为：空态 = 大拖放面板（主按钮「选择视频文件」）；
  有文件态 = 双栏（预览卡 + 参数卡）
- 转换页操作条（空闲）放**次级描边**按钮「添加视频到队列」（打开选择器，语义=入队）
  + 次级按钮「前往队列」（跳转到队列页，开始转换在那里）
- 运行中时操作条显示「取消当前」「全部停止」+ 进度

### P0-2 队列页状态矛盾

现状：列表上方恒显示「队列空闲」，同时右上角写「共 4 项 · 等待中 4」——自相矛盾。

修正：

- `ProgressSummary` 默认值从「队列空闲」改为空字符串（不再有恒定的空闲文案）
- 两个页面的进度条 + 进度文本**仅在 `IsRunning` 时显示**（转换页已是此行为，队列页对齐）
- 队列结束时不留下过期文案：`OnQueueFinished` 里百分比归零、`ProgressSummary` 清空，
  结果由底部状态栏呈现（`完成 4 个，失败 0 个，取消 0 个`）

### P0-3 转换页空间利用

- 缩略图从 220x124 放大到 320x180（16:9），预览卡按可用宽度伸展
- 双栏保持：预览卡 `*`、参数卡固定 400 DIP；两卡 `VerticalAlignment="Top"`

### P1-1 队列项信息层级

- 每项加**进度条**：等待中 0%、运行中实时百分比、已完成 100%、失败保持最后值
  （`QueueItem` 新增 `ProgressValue`，在 `UpdateProgress` / `RaiseAll` 里通知）
- 目标格式加箭头前缀（`→ MP4 · 自动`），参数变化时随 `TargetSummary` 刷新
- 状态文字放大到 12px；四态颜色沿用 `StateToBrush`（灰/蓝/绿/红）

### P1-2 危险操作视觉区分

- 「全部停止」「清空队列」改用警示色（`SystemFillColorCriticalBrush`），
  「取消当前」「移除」「重试失败项」保持中性灰
- 「开始转换」保持蓝色填充主按钮

### P2 打磨

- 输出目录输入框加占位符「默认为源文件目录」（灰色，框内）
- ffmpeg 卡片加「复制版本号」按钮（复制 `FfmpegStatus`，便于排查）

### 已满足、无需改动（回复用户时说明）

- 转换页「缩略图时间点 / 重新截取」已只在有文件态渲染，空态不存在这些控件
- 队列页已有「清除已完成」按钮，等价于用户建议的快捷入口

## 约束

- 不改 Core 的转换/队列语义，不动 `IConversionQueue` / `IConversionService` 契约
- 队列页仍保留「开始转换」的 `AutomationId="ConvertButton"`；
  转换页新增按钮用新 id：`AddToQueueButton`、`GoToQueueButton`
- 页面跳转通过 `MainWindow` 暴露的内部方法实现，不在 VM 里塞导航逻辑

## 验收

- [ ] 转换页无「开始转换」；队列页有且仅有它一个主按钮
- [ ] 队列页空闲时不再出现「队列空闲」，与「共 N 项 · 等待中 N」不冲突
- [ ] 转换页缩略图放大、双栏无中间大空白
- [ ] 队列项可见进度条、目标格式、四态颜色
- [ ] 「全部停止」「清空队列」有警示色
- [ ] 构建 0/0 + 142 测试通过；三档尺寸逐页截图确认

### 自查发现的回归（已修）

放大缩略图后信息列被压到约 247 DIP，`重新截取` 按钮被挤出卡片——UIA 返回
`RecaptureButton = OFFSCREEN`，元数据第三项（1.7 MB）也被截断。

修正：文件卡改为三行结构 —— ①[缩略图 | 基本信息] ②整卡宽的
`缩略图时间点 + 重新截取` ③整卡宽的 `详细信息`；元数据行加 `TextWrapping="Wrap"`。
复测：`RecaptureButton = 817..927`（窗口 190..1960，有限且在窗内）、
`缩略图时间点` 可见、元数据三个值齐全。

这条也补进了 frontend spec 的教训：**控件放大后必须复测同一行其它控件的可达性，
不能只看截图**。
